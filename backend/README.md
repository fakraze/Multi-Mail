# Local Google OAuth check

1. In Google Cloud, enable the Gmail API, configure the OAuth consent screen, and create a **Web application** OAuth client. Add the Google account you will use as a test user if the app is in testing mode. Register this exact authorized redirect URI: `http://127.0.0.1:8000/auth/google/callback`.
2. From `backend/`, install dependencies with `python -m pip install -r requirements.txt`.
3. Copy `backend/.env.example` to `backend/.env` and replace the client ID and secret with the values from Google Cloud. The backend loads this file automatically; existing shell environment variables take precedence. Optionally set `GOOGLE_REDIRECT_URI` to another loopback URL whose path is `/auth/google/callback`, and set frontend `VITE_BACKEND_URL` to the matching backend origin. `FRONTEND_URL` defaults to `http://localhost:5173/`; set it to the exact local Vite home URL if different. Do not commit `backend/.env` or the credentials.
4. From `backend/`, run `python run.py`. This launcher disables HTTP access logs because callback URLs contain short-lived authorization codes. For auto-reload, use `uvicorn app.main:app --reload --no-access-log`; plain `uvicorn ... --reload` prints authorization codes in request logs.
5. From `frontend/`, run `npm install` and `npm run dev`. Click **Connect Gmail**, then **Continue with Google**.

On success, the backend verifies the Gmail address, saves the single connected account and OAuth credentials in ignored `backend/mail.db`, syncs the first Inbox page and Gmail history cursor, then redirects to the frontend with a non-secret `gmail=connected` marker. The database caches requested mailbox pages and message summaries, with at most 50 messages per page. Manual Refresh and the connected page's one-minute timer call `POST /api/mailbox/sync` with the current view parameters. The backend checks Gmail history from the saved cursor, refreshes the requested page after changes, and rebuilds it if history cannot continue. A successful sync commits the page and cursor together. Mail bodies are still read from Gmail. Opening the frontend home URL directly shows the original sample page, even if an older grant exists. If the old `backend/oauth_tokens.json` file exists, the first backend access verifies its account, migrates its credentials into SQLite, and removes the file. Keep `mail.db` private because it contains plaintext OAuth credentials and mail summaries. Reauthorizing the same account keeps its existing refresh token when Google does not return another; authorizing another account replaces the account and cache.

To verify Gmail API access, enable the Gmail API for the same Google Cloud project and run `python check_gmail_access.py` from `backend/` after authorization. The command reads the saved grant, calls Gmail's profile endpoint, and prints the authorized account address. If the access token has expired and the grant has a refresh token, it refreshes access in memory and retries once. It does not save Gmail profile data or refreshed tokens. The existing `gmail.modify` scope already authorizes this profile request and supports the planned star and label actions.

Run backend tests from `backend/` with `python -m unittest discover -s tests`.

To modify one message from the latest authorized account from the command line, run `python check_gmail_modify.py MESSAGE_ID star` or replace `star` with `unstar`. For a user-created Gmail label or Important, run `python check_gmail_modify.py MESSAGE_ID add-label --label-id LABEL_ID` or use `remove-label`. Message IDs come from the connected inbox API; editable label IDs come from its `labels` array. Category IDs are not editable. The command reads the stored database grant, changes only the requested message label, then reads that same message again and reports whether Gmail reflects the change. It does not print message content or credentials. The connected page uses `PATCH /api/messages/{message_id}/labels` for edits and `POST /api/labels` to create a user label. Current frontend API and database details are in the project root `README.md`.
